The app was supposed to generate accurate projections based on real data from multiple API sources, calibration buckets, and supporting calculations. Currently, it does not work reliably.

Known problems to investigate:
- Sync buttons are messy, disorganized, and unclear.
- Sync buttons often spin forever or fail silently.
- Data does not always complete syncing.
- Data displayed in the UI appears inaccurate.
- Projection logic is unreliable.
- Calibration buckets may not be applied correctly.
- Some areas of the app do not make logical sense.
- Fixes are being patched in one component instead of solving the underlying system problem.
- One fix often breaks another feature.
- Math and calculations may be wrong, inconsistent, duplicated, or stale.

Your job:

First, audit before changing anything.

Do not immediately patch random components.

Map the current system:
- Which APIs are being used?
- Where does each data source enter the app?
- Where is the data transformed?
- Where is it stored?
- Which tables/collections are involved?
- Which services calculate projections?
- Which files calculate calibration, edge score, confidence, probability, expected value, or recommendation tiers?
- Which frontend components display those values?
- Which sync buttons call which backend routes?
- Which backend routes call which services?
- Which functions can fail silently?
- Which functions can hang indefinitely?
- Which calculations are duplicated across files?
- Which values are being recomputed instead of stored as snapshots?
- Which values are stale, missing, nullable, or being assumed incorrectly?

Then verify the math.

For every projection-related calculation, identify:
- Formula name
- File path
- Inputs
- Output
- Expected behavior
- Current behavior

- Whether the formula is used consistently
- Whether the frontend and backend agree
- Whether values are rounded too early
- Whether percentages, decimals, odds, probabilities, and multipliers are mixed incorrectly

Then audit sync behavior.

For each sync button:
- Identify its frontend component.
- Identify the function it calls.
- Identify the API route it hits.
- Identify the backend service that runs.
- Identify what data it is supposed to fetch.
- Identify where the data should be saved.
- Identify what success means.
- Identify what failure means.
- Identify what the UI should show during loading, success, partial success, and failure.
- Identify why it may spin forever.
- Identify whether the button can be clicked repeatedly and cause duplicate jobs.
- Identify whether sync jobs need deduplication, locking, timeout handling, or job status tracking.

Then audit UI logic.

Identify areas where the app does not make logical sense:
- Buttons in confusing places
- Duplicate sync controls
- Missing explanations
- Misleading labels
- Values shown without source transparency
- Projections shown without confidence/context
- Scores shown without enough data
- Empty states that look like bugs
- Loading states that never resolve
- Error states that do not explain what failed
